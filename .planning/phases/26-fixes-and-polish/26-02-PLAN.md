<objective>
POL-02: raise the main-image WebP quality from 80 to 85 and install the automated text-edge regression gate that proves the change does not smear composited typography.

Purpose: Phase 23 moved text rendering into a deterministic server-side compositor, which made compression artifacts around glyph edges the dominant remaining output-quality defect. Quality 80 was chosen in v1.1 for storage cost when text was AI-rendered into the raster and edge fidelity did not matter. It does now.
Output: a one-line constant change that propagates to every call site, plus a standalone `tsx` gate that measures real edge energy on a real composited render.
</objective>

Pipeline:
1. Read `tests/fixtures/typography/high-contrast-1024.png` and `tests/fixtures/typography/strings.json`.
2. `const { buffer: composited, meta } = await compositeTypography({ baseImageBuffer, textBlocks: strings.pt_br, layoutArchetypeId: "bottom_band" })`. 3. `const region = computeArchetypeRegion("bottom_band", 1024, 1024)`.
4. Define `async function edgeEnergy(buf: Buffer): Promise<number>` = `sharp(buf).extract(region).greyscale().convolve({ width: 3, height: 3, kernel: [0,1,0,1,-4,1,0,1,0] }).stats()` -> `channels[0].stdev`. Extract BEFORE greyscale/convolve so the kernel never sees pixels outside the text region.
5. `const groundTruth = await edgeEnergy(composited)` (the lossless PNG).
6. For `q of [40, 80, 85, 95]`: `const { buffer } = await optimizeImage(composited, q); ratios[q] = (await edgeEnergy(buffer)) / groundTruth;`
7. Always print the full ratio table (`q=40 ratio=0.xxx` ...) BEFORE the assertions so the threshold is auditable and re-calibratable from one run's output.
