<objective>
Turn the planning call into a strict structured-output call and make schema failures loud instead of silent.

Purpose: PLAN-02. Today `generateText`'s `try { attempt1 } catch { try { attempt2 } catch { buildLocalTextFallback() } }` treats a JSON parse error and a network timeout identically — both silently produce a generic templated post, logged only to `console.error`. CONTEXT.md locks the fix: schema failures become real, logged, user-visible generation errors; transport failures are UNCHANGED.
Output: `json_schema` / `responseSchema` on the request; `PlanningSchemaError` thrown on double schema failure; a `planning_schema_failure` row in `generation_logs`; a route-level guard so `buildTextFallback` can never absorb it.
</objective>
