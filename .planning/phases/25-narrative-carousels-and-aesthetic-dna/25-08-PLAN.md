```typescript
function getStorageObjectPathFromPublicUrl(publicUrl: string | null | undefined, bucket: string): string | null {
    if (!publicUrl) return null;
    try {
        const url = new URL(publicUrl);
        const marker = `/storage/v1/object/public/${bucket}/`;
        const markerIndex = url.pathname.indexOf(marker);
        if (markerIndex === -1) return null;
        const encodedPath = url.pathname.slice(markerIndex + marker.length);
        const decodedPath = decodeURIComponent(encodedPath).replace(/^\/+/, "");
        return decodedPath || null;
    } catch { return null; }
}
```

**`GET /api/admin/style-reference-photos`**
- `requireAdminGuard` first.
- Optional query filters `scope` and `style_id`. When `scope` is present it must be a member of `STYLE_REFERENCE_SCOPES`, else 400.
- `createAdminSupabase().from("style_reference_photos").select("id, scope, style_id, photo_url, position, created_at")`, applying `.eq()` for each present filter, `.order("style_id").order("position", { ascending: true })`.
- Respond `styleReferencePhotosResponseSchema.parse({ photos: data ?? [] })`.
- This single unfiltered call is what the admin card uses to render every board at once.

**`POST /api/admin/style-reference-photos`**
- `requireAdminGuard` first; capture the admin's user id from its result for `created_by`.
- `createStyleReferencePhotoSchema.safeParse(req.body)`; on failure 400 with the joined Zod messages (same wording style as `brand-references.routes.ts`).
- Cap check: count existing rows for `(scope, style_id)`; when `>= MAX_STYLE_REFERENCE_PHOTOS` respond 400 `{ message: "Maximum 8 reference images allowed per style" }`.
- Auto-position: `max(position) + 1` for that `(scope, style_id)`, defaulting to 0 — mirror the `maybeSingle()` pattern exactly.
- Insert, `.select(...).single()`, respond 201 with `styleReferencePhotoSchema.parse(row)`.

**`DELETE /api/admin/style-reference-photos/:id`**
- `requireAdminGuard` first.
- Fetch `id, photo_url` — 404 when missing.
- Delete the DB row first (immediate UI consistency); 500 on failure.
- Best-effort storage delete via `getStorageObjectPathFromPublicUrl(photo.photo_url, "user_assets")` + `.storage.from("user_assets").remove([path])`; a failure is `console.warn`-ed only, never surfaced.
- Respond `{ success: true }`.

Do NOT add a public (non-admin) GET route: generation-time reads go through `fetchStyleBoardPhotoUrls` in `style-reference.service.ts` using the service-role client, and the creator UI has no need for these images.
