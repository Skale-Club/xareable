
    ```typescript
    export const ASPECT_RATIO_TOLERANCE = 0.005;
    export async function cropToExactAspectRatio(buffer: Buffer, aspectRatio: string): Promise<Buffer>
    ```
    Algorithm (exact):
    1. `const parsed = parseAspectRatio(aspectRatio); if (!parsed) return buffer;`
    2. `const image = sharp(buffer); const { width = 0, height = 0 } = await image.metadata(); if (!width || !height) return buffer;`
    3. `const target = parsed.w / parsed.h; const current = width / height;`
    4. If `Math.abs(current - target) <= ASPECT_RATIO_TOLERANCE` return `buffer` unchanged (no re-encode — avoids a needless lossy pass before the compositor).
    5. If `current > target` → source too wide: `cropWidth = Math.max(1, Math.round(height * target)); cropHeight = height;`
       Else → source too tall: `cropWidth = width; cropHeight = Math.max(1, Math.round(width / target));`
    6. Clamp: `cropWidth = Math.min(cropWidth, width); cropHeight = Math.min(cropHeight, height);`
    7. `const left = Math.max(0, Math.round((width - cropWidth) / 2)); const top = Math.max(0, Math.round((height - cropHeight) / 2));`
    8. `return image.extract({ left, top, width: cropWidth, height: cropHeight }).png().toBuffer();`
       Use `.png()` explicitly — the compositor consumes this buffer next and must not receive a lossy intermediate (the final WebP pass happens once, later, in `processImageWithThumbnail`).
    9. Wrap steps 2-8 in try/catch; on any error `console.warn("[image-crop] crop failed, returning original:", err)` and `return buffer`. A crop failure must never break a generation.

    Also export a small helper used by the harness and by the routes' logging:
    ```typescript
    export async function measureAspectRatio(buffer: Buffer): Promise<{ width: number; height: number; ratio: number } | null>
    ```
    returning `null` on unreadable metadata.

    Add a JSDoc note on `cropToExactAspectRatio` recording the 23-RESEARCH.md Open Question 3 consequence: extreme ratios (`1:8`, `8:1`, `4:1`, `1:4`, `21:9`) may discard a large share of the generated frame, so the negative-space prompt instruction (plan 23-05) accounts for a larger crop margin on those.
