# Phase 21.1 Plan 04: Generate/Edit Route Affiliate Gateway Gate Summary

**Affiliate-aware OpenRouter key gate replaces the bare Gemini hard gate in `/api/generate` and `/api/edit-post`, while both routes keep an unchanged, non-fatal Gemini key resolution feeding the frozen direct-Google video branch.**

## Accomplishments

- `/api/generate`: affiliates now gate on `getOpenRouterApiKey(profile)` instead of the old unconditional `getGeminiApiKey(profile)` hard gate — an affiliate with only an OpenRouter key configured is never locked out of image/caption generation (closes 21.1-RESEARCH Pitfall 1).
- `/api/edit-post`: same affiliate-aware gate, replacing the dead hardcoded "configure your own Gemini API key" message with the exact SC3 OpenRouter error string.
- Both routes retain a second, non-fatal `getGeminiApiKey` resolution specifically for the GATE-08-frozen `generateVideo()` direct-Google call, with a pre-SSE 400 guard (`isVideo && !geminiApiKey` / `isVideoPost && !geminiApiKey`) that fails fast with an actionable Settings pointer instead of handing `generateVideo` an empty key mid-stream.
- `createGeminiService` (generate.routes.ts only — edit.routes.ts never calls it), `selectImageApiKey` (both routes, all image call sites), and `ensureCaptionQuality` (both routes) now receive the affiliate's resolved `openRouterApiKey`.
- Eliminated the `let imageApiKey = geminiApiKey; if (provider.name === "openai") {...}` Pitfall-3 pattern in both routes' image branches — replaced with `selectImageApiKey({ providerName, geminiApiKey, openRouterApiKey, openaiApiKey })`.
