Output: Both routes resolve, gate on, and thread the affiliate's OpenRouter key end-to-end for all gateway work, and both still resolve a Gemini key for video.

## THE TWO KEYS COEXIST — READ THIS BEFORE EDITING

These two routes are the ONLY files in the phase where BOTH resolvers stay. They
gate different code paths in the same handler:

| Key | Resolver | Used by |
|-----|----------|---------|
| `openRouterApiKey` | `getOpenRouterApiKey(profile)` — affiliates only, `""` otherwise | `createGeminiService` (planning/text), `selectImageApiKey` → `provider.generate/edit`, `ensureCaptionQuality` |
| `geminiApiKey` | `getGeminiApiKey(profile)` — **UNCHANGED**, hard-gated for non-affiliates, non-fatal for affiliates | `generateVideo(...)` (GATE-08 direct-Google / Veo), `enforceExactImageText(...)` (direct-Google `x-goog-api-key` + legacy `editImage`) |

**Do NOT collapse this into a single `if (ownApiKey) { ... } else { ... }` that leaves
`geminiApiKey = ""` for affiliates.** Affiliates have unconditional, billed, live
access to video today (`isVideoLocked` is false for affiliates in
`post-creator-dialog.tsx:911`) and `generateVideo` has no fallback and no empty-key
guard — that collapse is a silent production lockout of a live billed feature. The
locked CONTEXT.md decision keeps a Gemini key field in affiliate Settings
(relabeled `"Gemini API key (used for video generation only)"`, plan 07) precisely
so this keeps working.

**Canonical affiliate-aware gateway key gate + video carve-out (apply verbatim, adapting only the profile variable name and the error-response shape already present in each handler):**

```typescript
const ownApiKey = usesOwnApiKey(profile);

// ── Phase 21.1 (GATE-06) affiliate-aware GATEWAY key gate ──
// A BARE getGeminiApiKey() hard gate here would 400 every affiliate who
// configured only an OpenRouter key. Affiliates gate on their own OpenRouter
// key; non-affiliates keep the platform Gemini gate verbatim. openRouterApiKey
// stays "" for non-affiliates on purpose: every gateway call site already falls
// back to config.OPENROUTER_API_KEY when it is empty.
let geminiApiKey = "";
let openRouterApiKey = "";
if (ownApiKey) {
    const { key, error } = await getOpenRouterApiKey(profile);
    if (error) { /* the handler's existing 400 error-response shape */ }
    openRouterApiKey = key;
} else {
    const { key, error } = await getGeminiApiKey(profile);
    if (error) { /* the handler's existing error-response shape, unchanged */ }
    geminiApiKey = key;
}

// ── Phase 21.1 (GATE-06) — GATE-08 video carve-out ──
// Video is a DIRECT-GOOGLE call (generateVideo → Veo), never an OpenRouter
// gateway call, so it needs a Gemini key even for affiliates. Resolve it
// NON-FATALLY: a missing Gemini key must not block an affiliate's image /
// caption work, which is fully OpenRouter-backed. The isVideo guard below
// enforces it; enforceExactImageText() (also direct-Google) already degrades
// gracefully inside its own try/catch.
if (ownApiKey) {
    const videoKeyRes = await getGeminiApiKey(profile);
    geminiApiKey = videoKeyRes.error ? "" : videoKeyRes.key;
}
```

Ordering matters: the `else`-branch `await getGeminiApiKey(` must be the FIRST
occurrence in the file so the harness's `gateIsConditional()` sees
`await getOpenRouterApiKey(` → `} else {` → `await getGeminiApiKey(`. Keep the
video carve-out block strictly AFTER the gate.
