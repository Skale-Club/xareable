### Parallel-execution git race (process note, not a plan deviation)

While staging Task 1's commit, a concurrent agent (plan 21.1-03, working in the same shared working directory with no worktree isolation) had staged `server/services/caption-quality.service.ts` between this agent's `git status` check and `git commit` call, causing the first commit attempt to sweep up their file. Caught immediately via `git show --stat HEAD` (showed 2 files instead of the expected 1), fixed via `git reset --soft HEAD~1` + `git reset HEAD -- server/services/caption-quality.service.ts` + re-commit, since `HEAD` had not moved further in the interim. Re-verified the resulting commit (`8c7e0d9`) contains only `image-provider.ts`. No content was lost; the other agent's staged-but-uncommitted change was left intact in their working tree for them to commit themselves. Same precedent as the documented 21-03/21-07/21-08/21-09 races from Phase 21 execution.
