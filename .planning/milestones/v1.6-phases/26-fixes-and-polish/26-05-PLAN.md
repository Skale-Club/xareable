CLI:
```
npx tsx scripts/reconcile-openrouter-costs.ts --from=2026-08-01 --to=2026-08-31
```
- `--from` / `--to` are inclusive ISO dates. Default when omitted: the previous calendar month, computed from `new Date()`.
- Parse with plain `process.argv.find(...)` regex matching (this repo's convention — no argument-parsing dependency).

Behavior:
1. `createAdminSupabase()`. If `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` are absent, print a clear message and `process.exit(0)` — never throw, never exit non-zero for a missing-credential run, so the script can be sanity-executed in a sandbox exactly like `scripts/verify-critic-live.ts`'s no-key path.
2. Page through `usage_events` (`.gte("created_at", from).lte("created_at", toExclusiveEnd)`) selecting `created_at, event_type, text_model, image_model, cost_usd_micros, charged_amount_micros, platform_net_micros`, using `.range()` pagination in blocks of 1000 until a short page returns. Aggregate IN PROCESS — this codebase does not use Postgres RPC for admin aggregates.
3. Print three tables via plain `console.log` (no table library):
   - **By day**: date, event count, `SUM(cost_usd_micros)`, `SUM(charged_amount_micros)`, implied markup ratio.
   - **By model**: model slug (prefer `image_model`, fall back to `text_model`, bucket nulls as `(unknown)`), event count, `SUM(cost_usd_micros)`.
   - **Grand total**: total events, total real cost in USD (micros / 1e6, 6 decimals), total charged, total platform net.
4. Print a trailing `NEXT STEP` block instructing the operator to open the OpenRouter dashboard for the same date range, compare the grand-total real cost, and apply the runbook's threshold. State plainly in that output that this script CANNOT fetch the dashboard side — there is no OpenRouter usage-API integration in this codebase, and adding one is out of scope for POL-08.
5. Header comment must state: (a) POL-08, plan 26-05; (b) this is a manual audit aid, deliberately not scheduled; (c) `usage_events` is the source of truth and `generation_logs` is only for explaining a delta.

Do NOT: query `generation_logs` for a second cost total; write anything to the database; import this script from `server/`; add it to `.github/workflows/`; add it to `server/services/cleanup-cron.service.ts`.

Write `docs/cost-reconciliation-runbook.md` mirroring `docs/production-cron.md`'s structure. Required sections:

1. **Header** — title, `**Created:** 2026-07-28`, `**Requirement:** POL-08 (v1.6)`, `**Status:** scheduled, not yet run`, and a bold one-liner: this audit **does not gate** the v1.6 milestone close.

2. **Why this exists** — the OpenRouter gateway migration (Phase 21) replaced a static token-pricing estimate with OpenRouter's real per-request `usage.cost`. Until one full billing period of real traffic has accumulated, there is nothing to reconcile. The risk being controlled: a systematic mis-attribution between what OpenRouter bills the platform and what `usage_events` recorded, which would silently distort margin.

3. **Source of truth** — a short table, stated unambiguously:
   | Source | Role |
   |---|---|
   | `usage_events.cost_usd_micros` | **PRIMARY source of truth** — the real per-request cost recorded at charge time |
   | `usage_events.charged_amount_micros` | What the user was billed (cost + markup) — used to sanity-check the markup ratio, not the platform cost |
   | `generation_logs` (`event_kind='visual_critic'` / `'model_fallback'`) | **Investigation only** — never a second primary total. Use `metadata.reroll_cost_usd_micros` and fallback rows to EXPLAIN a delta after one is found |
   | OpenRouter dashboard export | The external comparison side. No API integration exists in this codebase; the operator exports it by hand |

4. **When to run** — the trigger rule, stated as a computable condition: one full billing period (30 days) after the first production deploy in which every AI call class routes through OpenRouter. Include the SQL to find that date:
   `select min(created_at) from usage_events where metadata->>'real_cost_usd_micros' is not null;`
   Add the run cadence after the first audit (quarterly) and name the owner (the platform operator / repo owner).

5. **Procedure** — numbered, copy-pasteable:
   - Step 1: run `npx tsx scripts/reconcile-openrouter-costs.ts --from=YYYY-MM-DD --to=YYYY-MM-DD` against production credentials; capture the grand total.
   - Step 2: export the same date range from the OpenRouter dashboard (Activity / Usage); capture its total spend.
   - Step 3: compute `discrepancy = |openrouter_total - usage_events_total| / openrouter_total`.
   - Step 4: apply the threshold (below).
   - Step 5: if over threshold, investigate using the three named `generation_logs` queries (include them verbatim: the `visual_critic` re-roll cost sum, the `model_fallback` count by `call_class`, and a per-day `usage_events` count vs. `generation_logs` count to detect unrecorded calls).
   - Step 6: record the outcome — date, range, both totals, discrepancy, verdict — in the log table at the bottom of this document.

6. **Material discrepancy threshold** — state a number and justify it in one sentence: **5%**. Under 5% is accepted as rounding/timing skew (a request billed by OpenRouter at the boundary of the export window lands in a different day bucket than `created_at`). At or above 5%, the audit fails and requires investigation before the next billing period.

7. **Known sources of benign delta** — a bullet list an operator would otherwise rediscover the hard way: critic re-roll costs (Phase 24) are platform-side and appear in OpenRouter's total but are excluded from the user's charge; fallback-model calls (Phase 21) bill at the fallback model's rate; affiliate BYOK generations (Phase 21.1) bill the AFFILIATE's OpenRouter account and must NOT appear in the platform dashboard total at all; day-boundary timezone skew between `created_at` (UTC) and the dashboard export.

8. **Audit log** — an empty markdown table with the columns from Step 6 and one italic row: *no audit has been run yet — see "When to run".*

Then add a one-line pointer to this runbook from `docs/README.md`'s index if that file maintains one (read it first; if it has no index, skip rather than inventing a section).
