<objective>
Invert the prompt: the image model must never render text again. Today FOUR independent channels still tell it to.

1. `buildTextModeInstruction()` says "Render these on-image text blocks EXACTLY as provided" — and Phase 22's PLAN-04 fix made that flow straight into the authoritative `image_prompt`.
2. The planning call's JSON schema REQUIRES a `structured_image_prompt.text_rendering` object whose field descriptions literally read "The headline text to render on the image" / `typography_style` / `text_placement` / `text_contrast`, while task 4 of the same prompt orders the model that "everything you put in `creative_plan.structured_image_prompt` must ALSO be expressed inside this paragraph" — i.e. the schema itself launders typography direction into `image_prompt`.
3. `buildImagePromptFromStructuredJson()` mechanically flattens that same `text_rendering` object into `Render this headline text prominently: "..."` / `Typography: ...` — and on the transport-failure path the flattened string WINS (`flattenedPrompt || image_prompt`).
4. `buildTextStyleInstruction()` emits literal image-facing type direction ("Typography directions: ultra-bold high-contrast sans-serif display typography, all-caps emphasis") concatenated DIRECTLY into `buildLocalTextFallback`'s `image_prompt` (no LLM in that loop) and into the planning prompt by `buildContextPrompt`.

If any of the four survives, the image model paints text that the compositor then draws over — exactly the ghosted/double-rendered failure TYPO-07 forbids, and a direct contradiction of TYPO-01's "text-free by prompt design."

Purpose: TYPO-01. Also resolves 23-CONTEXT.md's locked `text_mode` semantic shift.
Output: prompt + schema surfaces only — no route changes, no compositor changes.
